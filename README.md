# Автоответчик для личных сообщений Telegram-канала

Бот отвечает в теме личного обращения к каналу, показывает кнопки «Проблемы с заказом»,
«Сотрудничество», «Розыгрыш», «Другой вопрос» и «Предложить новость». После выбора «Розыгрыш» бот
просит победителя прислать username, ID Kupikod, ссылку на розыгрыш и занятое
место одним сообщением, показывает экран подтверждения и только затем сохраняет заявку в
`data/bot.sqlite3`. Каждому выбранному разделу присваивается номер обращения.
Администраторы видят исходное сообщение и ответ в том же диалоге канала.

## 1. Сразу перевыпустите токен

Токен, который был отправлен в переписке, больше нельзя считать секретным.
Откройте [@BotFather](https://t.me/BotFather), выполните `/revoke`, выберите бота,
а затем получите новый токен. Старый токен использовать нельзя.

## 2. Настройте канал

1. В профиле канала откройте **Изменить → Личные сообщения** и включите их.
2. Добавьте созданного бота администратором канала.
3. Выдайте ему право **Управление личными сообщениями**
   (`can_manage_direct_messages`). Остальные права для этого сценария не нужны.

Telegram передаёт боту `direct_messages_topic.topic_id`; при ответе бот указывает
тот же `direct_messages_topic_id`. Поэтому сообщение приходит именно в личный
диалог подписчика с каналом, а не в отдельный чат с ботом.

## 3. Запустите

Требуется Node.js 22.5 или новее. Проект не устанавливает сторонние пакеты.

В PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
node --test
node src/bot.mjs
```

В `.env` замените `replace_with_new_token` на **новый** токен. Файл `.env` уже
исключён из Git. В `ADMIN_USER_IDS` через запятую указываются Telegram ID
администраторов, которым доступна панель обращений.

Для круглосуточного запуска на сервере с Docker:

```powershell
docker compose up -d --build
docker compose logs -f
```

Бот использует long polling, поэтому отдельный домен и HTTPS-сертификат не
требуются. Одновременно должен работать только один экземпляр бота.

## Поведение

- Первое сообщение подписчика временно сохраняется, после чего бот показывает
  меню из пяти разделов.
- После выбора раздела бот показывает текст и просит подтвердить отправку. До
  подтверждения обращение не создаётся и администратору не отправляется.
- До подтверждения текст можно полностью заменить или дополнить. После отправки
  также доступны «Исправить заявку» и «Дополнить заявку»; изменения добавляются
  в историю отдельными записями и не скрывают первоначальный текст.
- После подтверждения пользователь получает сообщение с номером обращения без
  меню. Пока это обращение открыто, каждое следующее обычное сообщение автоматически
  добавляется в его историю и не создаёт новое обращение.
- Когда пользователь или администратор завершает вопрос, обращение закрывается,
  а пользователь получает уведомление. Следующее сообщение после закрытия запускает
  создание нового обращения и выбор раздела.
- Закрытое обращение автоматически переносится в архив через 24 часа. История
  сообщений сохраняется и остаётся доступна в архиве администратора.
- При выборе «Проблемы с заказом» бот сразу сообщает, что канал не является
  службой поддержки, и показывает прямую кнопку перехода в
  [@KUPIKOD_bot](https://t.me/KUPIKOD_bot). Обращение в админ-панели при этом
  не создаётся. Кнопка «← Вернуться» возвращает к выбору другого раздела и
  сохраняет исходный текст сообщения.
- Команда `/menu` повторно показывает кнопки, если есть ожидающее отправки сообщение.
- Кнопка «Новое обращение» отменяет текущий ввод и просит написать новый текст.
- Перед сохранением данных розыгрыша пользователь может подтвердить или изменить
  сообщение. Исходный текст сохраняется целиком без жёсткой проверки формата;
  распознанные Telegram username, ID Kupikod, ссылка и место сохраняются дополнительно.
- У каждого подтверждённого обращения есть номер и статус.
- Ответы администраторов не запускают автоматические сообщения.
- Обращения хранятся в таблице `tickets`, а подтверждённые заявки победителей —
  в таблице `giveaway_claims` SQLite-файла.

## Панель администратора

1. Каждый администратор должен один раз открыть личный чат с ботом и нажать **Запустить**.
   Telegram запрещает боту первым начинать личный диалог.
2. Команды `/start`, `/admin` и `/inbox` открывают панель.
3. Панель показывает количество новых, открытых и архивных обращений, а также
   отдельный список «✅ Закрытые» и фильтры «🛒 Проблемы с заказом», «🎁 Розыгрыши»,
   «🤝 Сотрудничество», «💬 Другие» и «📰 Предложить новость». Закрытые обращения остаются в этом списке
   24 часа, после чего автоматически перемещаются в «🗄 Архив».
4. В карточке видны канал, отправитель, Telegram ID, дата, раздел, статус,
   количество сообщений и текстовая история последних 20 сообщений и ответов.
   Во всех списках обращения отсортированы от более ранних к более поздним:
   сначала меньшие номера, затем большие.
5. Кнопка **Ответить** включает режим ответа. Следующее сообщение администратора,
   включая фото или документ, отправляется пользователю в исходный диалог канала.
   Команда `/cancel` отменяет режим ответа.
6. Обращение можно закрыть, возобновить, отправить в архив или вернуть из архива.

При создании нового обращения бот отправляет администратору отдельное уведомление
с кнопками быстрого просмотра и ответа. Дополнения сохраняются в истории и снова
помечают обращение непрочитанным, но не отправляются администраторам отдельными
сообщениями. Непрочитанное обращение помечается символом `●`, прочитанное — `○`.

## Проверка перед публикацией

Напишите каналу с обычного пользовательского аккаунта, выберите каждую кнопку и
проверьте ветку «Розыгрыш» сначала с неверным текстом, затем с `@username`.

Официальная документация: [личные сообщения каналам в Bot API](https://core.telegram.org/bots/api#directmessagestopic)
и параметр [`direct_messages_topic_id`](https://core.telegram.org/bots/api#sendmessage).
